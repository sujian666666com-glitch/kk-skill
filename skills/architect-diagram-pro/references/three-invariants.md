# 三不变式（语义层核心心智模型）

本文档所有规则与禁令，都是以下三条不变式的推论。理解它们即可正确应对任何未列举的场景——**原则优先于规则**。

### 不变式 1：解引用一切（Dereference Everything）

本地渲染虽在用户机器，但「悬空引用」会让图结构空洞。发出绘图前必须把所有引用拍平为自包含的语义文本：

| 悬空引用 | 解引用动作 |
|---|---|
| 文件路径（"请参考 `/path/to/x`"） | 先读取该文件，将其核心逻辑拍平为纯文本写入绘图意图 |
| 专有名词/缩写（未释义术语） | 补全最小信息集：角色（对象类型与责任边界）、层级（所属模块/抽象层）、动作（关键行为）、上下游关系 |
| 旧图上下文（"基于上一张图修改"） | 把现有图结构随请求重新提交；不要求用户重复输入全部内容 |

- 未释义的术语不得直接作为节点标签、分组标题或关系端点（禁止「仅列词成框」）。
- 若输入仅含术语清单，先补全最小信息集，再进入结构决策。

### 不变式 2：论证而非展示（Argue, Not Display）

- 图结构必须服务于语义论证：概念层级、因果关系、依赖链路是结构主线。
- 每条关系必须可复述为明确语句（如"A 依赖 B""C 触发 D"），禁止用「元素靠得近」替代关系定义。
- 同构校验：移除文字标签后，结构本身仍应能传达核心逻辑。

### 不变式 3：一图一主题（先定层级，再定粒度）

采用多级抽象：宏观图展示全局脉络与骨架，中观图展示子系统/模块间交互，微观图展示具体执行逻辑。**不要在一张图里展示所有内容**。

- 先识别信息焦点与抽象层级，再决定画多细。
- 单图装不下时必须拆分（见 clarification-gate.md 的确认门）。

## 展示意图边界

| 支持：语义级展示意图（可直接采用） | 不支持：像素级精确诉求（必须降级翻译） |
|---|---|
| 配色基调（"基础设施用蓝色系"） | 指定具体 hex 色值并要求严格一致 |
| 重点突出（"高亮这条链路""这个模块要醒目"） | 指定精确坐标 / 像素位置 |
| 聚类分组（"订单域的模块放在一起"） | 指定字号、线宽、间距的具体数值 |
| 分层结构（"按接入层/应用层/数据层上下排"） | 指定复杂自定义布局算法 |

- 布局、坐标与渲染由生成轨道决定，本 skill 无法也不应承诺像素级精确呈现。
- 遇到像素级诉求时：将其**翻译为最接近的语义级意图**传入绘图意图（如"放在右上角"→"作为边缘支撑组件，与主链路分离"），并可告知用户最终布局由渲染自动决定。
- 若用户坚持花哨设计，优先保证图的论证性（不变式 2），展示诉求让位于结构正确性。

## 输出前自检（不变式维度）

- [ ] 所有本地文件引用是否已拍平为文本？（不变式 1）
- [ ] 是否存在未释义的专有名词？（不变式 1）
- [ ] 每条关键关系是否可复述为明确语句？（不变式 2）
- [ ] 图的层级与粒度是否匹配信息焦点？是否该拆分？（不变式 3）
- [ ] 用户的展示诉求是否已翻译为语义级意图？（展示意图边界）
