# 澄清前置与确认门（人机协作层）

## 一、前置澄清三问（格式 / 类型 / 范围不清时必问）

动手前若以下任一项不明确，**用不超过 3 个选项的提问确认**，不要猜：

1. **输出形态**：自包含 HTML 文件（可分享）｜内联 SVG（对话中直看）｜Mermaid 代码块（贴进文档）？
2. **图表类型**：用户说的是上表（capability-matrix.md ✅）哪一种？概念有歧义时复述确认（如「你说的是业务流程图，对吗？」）。
3. **范围与粒度**：画整体还是某个模块？节点上限建议 ≤20，超出先提议拆分。

> 仅在用户意图、类型、输出形态都明确时才直接开画；**「先理解，再绘制」优先于「先出图」**。

## 二、意图澄清交互（风格决策前置）

用户的呈现逻辑（图类型）、构图范式或配色基调不明确时，在落笔前必须先澄清：

- **呈现逻辑倾向**（四选一）：组件拓扑（系统/模块/服务关系）／流程逻辑（步骤/分支/因果）／混合（流程为骨架、组件为落点）／思维导图树形（根节点逐层展开）。
- **构图范式倾向 Morphology**（三选一）：包容式 `container`（底板分区包裹，浅色 Zone 圈定域，适架构/中台）／流转式 `flow`（强调连线与信号，以链路为叙事，适流程/数据流/调用链）／陈述式 `editorial`（文本排版与留白，适科研框架/逻辑推导）。
- **配色基调倾向**：科技蓝、暖色、深色等语义级描述（不承诺 hex 严格一致）。

> 用户回答"随便/你决定"时：自主选择最匹配的风格并在绘图意图中写明依据，禁止留空交给默认猜测。用户请求已明确（如"画一张蓝白配色的分层架构图"）时跳过提问。

## 三、确认门（多视图拆分阻塞等待）

> 触发条件：判定需要拆分为 `layers`（独立视图）或 `scenarios`（单数据源 + 高亮）时，在落笔前必须先向用户输出拆分推荐方案并**阻塞等待明确确认**。

**推荐方案必备字段**：
- 拆分机制（`layers` 还是 `scenarios`）
- 每个视图的名称 / 聚焦点 / 抽象层级（宏观 / 中观 / 微观）
- 拆分理由

**阻塞语义**：用户未明确确认前，**禁止**落笔、**禁止**调用生成动作。

**用户拒绝或修改**：按用户意见重新生成方案（可给改为单图、减少视图数、调整划分等选项），再次等待确认，不得擅自按原方案执行。

**豁免条件**：用户请求中已显式指定拆分方式（如"拆成 9 个视图，每个聚焦一个子系统"）时视为已确认，跳过确认门；判定单图即可承载时不触发。

## 四、Scenarios 高亮（优于复制多份图）

同一架构上高亮不同链路（如 Query 链路 vs Callback 链路）时，用 **scenarios**：维护一份含全部节点与连线的基础图，再为每条链路定义视图——淡化无关组件、高亮目标链路。**禁止要求复制拼接多份完整图形**。

> 只需在绘图意图中用自然语言表达拆分与高亮意图（如"拆分为订单域、支付域两个独立视图""淡化缓存等无关组件，高亮从网关到订单服务的链路"），具体语法由生成轨道决定。
