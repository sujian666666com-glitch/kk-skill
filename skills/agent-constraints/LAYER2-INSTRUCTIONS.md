# 第 2 层：常驻指令（AGENTS.md / CLAUDE.md）

只放**无法自动化、无法从代码推断、且全局恒真**的内容。

## 写什么，不写什么

| 写 | 不写 |
|---|---|
| 猜不到的命令（`uv run pytest`、非标准 test runner） | 目录结构、技术栈概览、模块说明 |
| 环境怪癖（必需的 env var、必须加 `--no-cache` 否则假阳性） | README 的复述、架构图 |
| 与工具默认值不同的约定 | 语言的标准惯例 |
| 非功能性要求（安全、性能边界） | 实现细节 |
| 保留性约束（"这里是自定义中间件，不要改成标准实现"） | 详细 API 文档，给链接即可 |
| 危险区（"`legacy/` 已废弃但生产在 import"） | 高频变动的信息 |
| 仓库礼仪（分支命名、PR 规范） | "写干净的代码"这类自明之理 |
| 决策理由（为什么选了这个反直觉的方案） | 逐文件说明 |

**非功能性要求那一行值得单独强调**：只有约 15% 的项目写它，但它恰恰最不可能从代码里推断出来。

## 写法细则

- **祈使句 + 精确命令**，不要描述性散文。
- **可验证的完成标准**：给退出码，不给形容词。「提交前跑 `uv run pytest -q`，全绿才算完成」优于「确保代码经过充分测试」。
- **`Never` 只留真正的红线**，且必须能被人一眼判定是否违反。写在这里的 Never 单次命中率在 45%–84% 之间，**主要取决于它要被应用多少次**：只需判定一次的（"不要 push 到 main"）偏高端，每个函数都要遵守的（尤其在改存量代码时）掉到四成多。后者必须同时配 hook 或 `permissions.deny`。
- **强调最多一处**。很多行都标 `IMPORTANT` 等于没有一行重要。
- **零冲突**。两条规则矛盾时模型可能任意挑一条。定期检查父子目录文件之间、以及与 `.claude/rules/` 之间的矛盾。
- **按场景分节**（`## 写代码时` / `## 评审时`）让 agent 按上下文取用，而不是逐条解析全文。

## HTML 注释技巧

Claude Code 在注入前会**剥离块级 HTML 注释**。把每条规则"因何而生"记在注释里，人能读到、维护时能判断该不该删，而不占用上下文：

```markdown
<!-- 2026-08-12 加入 uv 规则：agent 连续三次用 pip 装依赖，破坏 lockfile。 -->
```

注意这是 Claude Code 的特性。Codex 与 Copilot 是否同样剥离未经核实，跨工具团队要留意它仍会计入那些工具的预算。

## 修剪判定表

逐条过一遍现有文件，按此处置：

| 判定 | 处置 |
|---|---|
| 目录结构 / 技术栈概览 / 架构说明 / README 复述 | **删** — 实证无收益，且制造双事实源 |
| 语言标准惯例、"写干净的代码"这类自明之理 | **删** |
| 已被 CI / linter / formatter 覆盖的 | **删** — 已在第 1 层 |
| **指向外部文档、计划或项目状态的** | **先核对该对象是否仍成立**——计划做完了、文档删了、阶段过去了，规则就是过期的。过期规则不会静默失效，**它会被照常执行**，代价比没有规则更高 |
| **要求读取大文档的**（"实现前先读 X、Y、Z"） | **算一遍引发的读取量**。指令本身两行，引发的可能是每会话几万 token。改成"遇到架构问题时参考"，把每会话成本改成按需成本 |
| 风格偏好但没有配套检查命令 | **删，或配 lint 后只留命令** |
| 详细 API 文档 | **换成链接** |
| 需要反复应用的强约束 | **保留，但补一个 hook** |
| 多步骤流程、检查清单 | **移到 Skill** |
| 只在某类文件上成立的 | **移到 path-scoped rule** |
| 与另一条规则矛盾的 | **必须解决**，不能两条都留 |
| 猜不到的命令、环境怪癖、非默认约定、危险区、决策理由 | **保留** |

改完之后反向检查一遍**缺什么**：安全边界、性能边界、危险区，这三类最容易缺失。

Claude Code 用户可以跑 `/doctor`，它会为已入库的 CLAUDE.md 提出删减建议——砍掉可从代码推断的部分，保留坑点、理由和非默认约定。

## 反模式

| 反模式 | 问题 | 改成 |
|---|---|---|
| `/init` 生成后直接提交 | 论文作者直接建议暂勿使用 LLM 生成的上下文文件 | 起草后大幅删减 |
| 写仓库概览 | 实证无收益，制造双事实源 | 删，除非仓库本身没文档 |
| 只写功能性要求 | 七成的人写架构和测试，只有 15% 写安全和性能 | 补上非功能性边界 |
| 把红线只写在文件里 | 反复应用时 65% 的运行至少违反一次 | 配 hook 或 `permissions.deny` |
| 靠"让 agent 复述规则"确认 | 确认过的仍有 28% 不合规，没确认的 63% 照样合规 | 确认无预测力，用 hook 或测试验证 |
| 父子目录文件复制粘贴 | 制造冲突指令 | 子文件只写差异 |
| 让文件替代重构 | 文件成了技术债的止痛药 | 规则反复出现说明代码库该改了 |
| 把长流程塞进常驻文件 | 每会话交税，多数任务用不到 | 做成 Skill |
| 把"多问澄清"写成常驻规则 | 自动化场景下可能直接不产出代码 | 改写规则本身：只在实质歧义时停。**不要搬去 Skill——"写代码"唤不醒**（见 `LAYER3-ONDEMAND.md`） |
| 把已有文档"摘要"进来 | 干活的是具体项（"匹配现有风格即使你有别的偏好"、"发现无关死代码只提不删"），摘要后只剩标题——**而标题就是无触发条件的形容词** | 连具体项一起搬，宁可多几行；要压缩就整条删掉，不要留空壳 |

## 加载与作用域

Claude Code 从当前工作目录**逐级向上**加载所有 `CLAUDE.md` 与 `CLAUDE.local.md`，全部拼接进上下文（不是覆盖），从文件系统根向下排列——离启动位置越近的越靠后读到。子目录里的文件则在 Claude 读到该目录文件时才加载。

monorepo 里被其他团队的祖先文件干扰时，用 `claudeMdExcludes` 按 glob 跳过。

模板见 `templates/AGENTS.md` 和 `templates/CLAUDE.md`。
