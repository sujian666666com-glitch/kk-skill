# 第 3 层：按需加载

判据：**在多数任务里都用不到的内容，不该每次进上下文。**

两种机制，选择取决于"什么时候需要它"。

| 触发方式 | 机制 |
|---|---|
| 碰到某类**文件**时 | path-scoped rule |
| 做某类**任务**时 | Skill |

---

## Path-scoped rules

放在 `.claude/rules/` 下的 markdown 文件，每个文件一个主题，文件名要有描述性（`testing.md`、`api-design.md`）。递归发现，可以用子目录组织。

**没有 `paths` frontmatter 的规则会无条件加载**，优先级等同 `.claude/CLAUDE.md`——这类文件等于第 2 层，要按第 2 层的标准审。

加上 `paths` 才真正变成按需：

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API 开发规则

- 所有端点必须做输入校验
- 使用统一的错误响应格式
```

- 支持多个 pattern 与花括号展开：`"src/**/*.{ts,tsx}"`
- 在 Claude **读到匹配文件时**触发，不是每次工具调用
- `~/.claude/rules/` 是个人级，先于项目规则加载，项目规则优先级更高
- 支持软链，可以把一套共享规则 link 进多个项目

Copilot 的对应物是 `.github/instructions/*.instructions.md` 的 `applyTo` frontmatter。

**什么时候用它而不是拆 AGENTS.md**：当一条规则只对前端 / 只对迁移 / 只对测试成立时。这比在根文件里写"如果你在改 X，那么……"更省，也更不容易被忽略。

## Skills

一个目录加一个 `SKILL.md`。目录名成为调用命令，`description` 决定 Claude 何时自动加载。

```markdown
---
name: release
description: 发布流程。当用户要发版、打 tag、或问发布步骤时使用。
---

# 发布流程

1. 确认 main 全绿：`npm run ci`
2. ...
```

要点：

- **正文只在被调用时加载**，所以长参考资料几乎零常驻成本
- `description` 是自动触发的唯一依据——**把关键用例写在最前面**，并带上用户可能说的原话。`description` 与 `when_to_use` 合计在技能列表里被截断到 1,536 字符
- **附属文件**放同目录，`SKILL.md` 里引用即可，只在需要时被读取。大段规格、示例集合都该放这里而不是主体
- `disable-model-invocation: true` 让它只能手动 `/name` 调用——**有副作用的流程应该设这个**
- `allowed-tools` 可以为调用它的那一轮预授权工具，避免权限打断；授权在用户下一条消息后失效
- 内容进入对话后会**一直留在上下文里**，但 Claude Code **不会在后续轮次重读文件**——所以要写成贯穿任务的常驻指令，而不是一次性步骤；改完 SKILL.md 需要新会话才生效

**什么内容该从 CLAUDE.md 搬进 Skill**：任何长成了"流程"而不是"事实"的一节。官方原话是——当你反复往对话里粘贴同一套指令、检查清单或多步流程时，就该建 Skill 了。

---

## 常见误用

**把项目的硬约束做成 Skill。** "不要直接 push 到 main"需要的是每个会话无条件在场，而 Skill 是模型判断相关时才加载。这是把第 2 层降级到了更不可靠的位置。硬约束应该往第 1 层走，不是往第 3 层。

**用 `paths` 规则表达安全边界。** 它只在 Claude 读到匹配文件时才进上下文——如果 agent 压根没读那个文件就动手了，规则不会出现。安全边界属于 `permissions.deny`。

**把「默认活动」做成 Skill。** Skill 靠模型判断 `description` 是否匹配来唤醒，可靠触发的前提是**触发词有辨识度**——"AGENTS.md"、"发布"、"剪视频"这种。而"写代码"、"实现功能"、"重构"是 agent 的**默认活动**，不是触发词：指望模型每次动手前先自问"我要不要加载纪律技能"，不现实。

> **唤不醒的按需规则等于规则不存在**，比一条略占上下文的常驻规则糟糕得多。
> 判断方法：把 `description` 的触发条件念一遍，如果它描述的是"agent 平时就在做的事"，那它就不该是 Skill。

**Skill 描述写得太泛。** `description` 决定自动加载，写成"代码规范相关"会导致该加载时不加载、不该加载时乱加载。写清楚触发场景和用户会说的原话。
