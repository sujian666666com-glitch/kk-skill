核验发现流行博客对这些论文的转述存在多处数字错误。原始论文链接见文末「出处」。

## 文件有效，但作用在合规率而非成功率

| 事实 | 数字 | 来源 |
|---|---|---|
| 无配置文件时目标指令执行率 | **0%**（524 次机会 0 次，Wilson 上界 0.73%） | McMillan |
| 有配置文件时 | **67.7%**（Cohen's h = 1.93） | McMillan |
| 任务成功率变化 | 自动生成 −0.5%/−2%（p=87%/37%）；手写 +2.4%（p=21%）——**均不显著** | Gloaguen |
| 推理成本 | **+20%／+23%**，p<0.001%，**显著** | Gloaguen |
| 合规率与任务质量的相关 | ρ=+0.104；控制任务身份后**不可检出**（OR=1.25, p=0.58） | McMillan |

> 结论：文件是行为杠杆，不是性能增强器。两篇论文从不同路径独立得出同一件事。

## 文件层的失守结构

| 事实 | 数字 |
|---|---|
| 至少违反一次的运行占比 | **65.7%** |
| 首次漏执行的中位位置 | **第 4 个函数** |
| 漏过一次后的合规率 | 降到 **55%** |
| 只需应用 1–2 次的任务 | 82.6% / 84.4% |
| 需应用 15–17 次的任务 | 45.1% – 72.7% |
| **改存量代码 vs 写新代码** | **45.1% vs 71.3%，差 26.2pp**（同代码库内最大落差） |

> 结论：hook 的职责不是替文件重复一遍，而是接住文件必然会漏掉的尾巴。

## 文件怎么写测不出差别，别的因素差别很大

| 因素 | 效应量 |
|---|---|
| 有无配置文件 | +67.7 pp |
| 任务类型 | 39.3 pp |
| 模型（Sonnet 4.6 vs Opus 4.6，同配置） | 12.8 pp |
| 代码库（两个 TS 项目，同配置） | 11.0 pp |
| 文件大小 / 位置 / 架构 / 冲突 | **测不出** |

文件大小实测：25 行 60.0%、100 行 65.2%、250 行 67.7%、500 行 64.0%（p=0.16）。
**最短的命中率最低**，趋势与"越短越好"相反。

> 引用零结果时的必要限定：每条件 50 次运行只能排除 15pp 以上的效应；对 10pp 的大小效应功效仅 70%。
> 因变量是一个平凡的静态注解，作者明说"是否迁移到更苛刻的指令是开放问题"。

## 概览类内容

- 论文小节标题即为 **"Context files are redundant documentation"**
- 仓库概览判定为 not helpful；但消融显示移除它也不显著变好（68.12% → 62.32%，p=0.15）——问题是整体信噪比
- **唯一正收益场景**：删除仓库全部文档后，上下文文件成为唯一文档，自动生成的文件一致提升 **2.7%**

## 人们实际在写什么（2,303 个文件 / 1,925 个仓库）

测试流程 75.9% ｜ 实现细节 70.8% ｜ 架构 68.1% ｜ **安全 14.8% ｜ 性能 14.5%**

> 七成在写被判定无收益的概览类内容；最不可推断的非功能性要求只有 15% 覆盖。
